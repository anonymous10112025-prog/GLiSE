# 🤝 Contributing to GLiSE

Thank you for your interest in contributing to **GLiSE** (Grey Literature Search Engine)!

This tool has been accepted at **MSR 2026** (Data and Tool Showcase Track) and we welcome contributions from the research community.

## 📋 Ways to Contribute

There are many ways to contribute to GLiSE:

- 🐛 **Report bugs** via [GitHub Issues](https://github.com/anonymous10112025-prog/GLiSE/issues)
- 💡 **Suggest features** or improvements
- 📝 **Improve documentation** (README, QUICKSTART, guides)
- 🧪 **Add tests** to improve code coverage
- 🔧 **Fix bugs** or implement new features
- 📊 **Share your research** that uses GLiSE
- ⭐ **Star the repository** to increase visibility

## 🎓 Academic Contributions

If you use GLiSE in your research:

1. **Cite our MSR 2026 paper** (see [README.md](README.md) for BibTeX)
2. **Star the repository** ⭐
3. **Share your results** — we'd love to hear about your work!
4. **Report issues** — help us improve the tool

## 🐛 Reporting Bugs

Before reporting a bug, please:

1. **Search existing issues** to avoid duplicates
2. **Check the [QUICKSTART.md](QUICKSTART.md)** for common problems
3. **Update to the latest version** of GLiSE

When reporting a bug, include:

- **Description:** Clear description of the bug
- **Steps to reproduce:** How to trigger the bug
- **Expected behavior:** What should happen
- **Actual behavior:** What actually happens
- **Environment:**
  - OS (Windows, macOS, Linux)
  - Python version (`python --version`)
  - GLiSE version
  - Installed packages (`pip freeze`)
- **Logs/Screenshots:** Any error messages or screenshots

## 💡 Suggesting Features

We welcome feature suggestions! Please:

1. **Check existing issues** to see if it's already proposed
2. **Describe the feature clearly:**
   - What problem does it solve?
   - How would it work?
   - Why is it useful for researchers?
3. **Tag it with `enhancement`**

## 🔧 Code Contributions

### Development Setup

1. **Fork the repository** on GitHub
2. **Clone your fork:**
   ```bash
   git clone https://github.com/anonymous10112025-prog/GLiSE.git
   cd GLiSE
   ```
3. **Create a virtual environment:**
   ```bash
   conda create -n glise_dev python=3.8
   conda activate glise_dev
   ```
4. **Install in editable mode:**
   ```bash
   pip install -e .
   ```
5. **Create a feature branch:**
   ```bash
   git checkout -b feature/your-feature-name
   ```

### Coding Guidelines

- **Follow PEP 8** style guide for Python code
- **Write clear docstrings** for functions and classes
- **Add comments** for complex logic
- **Keep functions focused** (single responsibility principle)
- **Use meaningful variable names**
- **Add type hints** where appropriate

### Testing

Before submitting a pull request:

1. **Test your changes** manually
2. **Ensure no regressions** — existing features still work
3. **Add new tests** if applicable
4. **Run the application** to verify it starts correctly

### Commit Messages

Write clear commit messages:

```
Add feature: description of the feature

- Detail 1
- Detail 2
```

Or for bug fixes:

```
Fix: description of the bug

Fixes #123
```

### Pull Request Process

1. **Push your branch** to your fork
2. **Create a Pull Request** to the `main` branch
3. **Fill in the PR template:**
   - Description of changes
   - Related issues (if any)
   - Testing done
4. **Wait for review** — we'll review and provide feedback
5. **Address feedback** if requested
6. **Celebrate!** 🎉 Your contribution is merged
